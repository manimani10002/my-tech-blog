지난 글에서는 C 코드가

```text
Source Code
→ Compile
→ Executable
```

과정을 거쳐 실행파일이 되는 과정을 살펴봤다.

이번에는 그 실행파일을 실제로 실행해보자.

```bash
./add
```

이 한 줄을 입력하는 순간 운영체제는 여러 작업을 수행한다.

```text
실행파일
 ↓
OS
 ↓
프로세스
 ↓
메모리
 ↓
CPU
```

이번 글에서는 이 과정을 **운영체제와 프로세스 중심**으로 살펴본다.

---

## 1. 프로그램과 프로세스는 다르다

먼저 프로그램과 프로세스를 구분해야 한다.

### 프로그램

디스크에 저장되어 있는 실행파일이다.

```text
add
```

아직 정적인 데이터다.

### 프로세스

실행 중인 프로그램이다.

즉

> 프로세스는 실행 중인 프로그램의 인스턴스다.

같은 프로그램을 여러 번 실행하면 동일한 실행파일을 기반으로 여러 프로세스가 만들어질 수도 있다.

---

## 2. 실행하면 운영체제가 개입한다

터미널에서

```bash
./add
```

를 입력하면 Shell이 운영체제에 프로그램 실행을 요청한다.

문서에서는 `fork()`와 `exec()`를 이용한 흐름을 다음과 같이 설명한다.

```text
사용자
 ↓
Shell
 ↓
fork()
 ↓
exec()
 ↓
OS Kernel
 ↓
프로세스 실행
```

`fork()`는 자식 프로세스를 만들고, `exec()`는 해당 프로세스의 메모리 내용을 실행할 프로그램으로 바꾼다.

---

## 3. OS는 프로세스의 메모리 공간을 만든다

프로그램을 실행하기 위해 운영체제는 프로세스에 독립적인 가상 메모리 공간을 제공한다.

문서에서는 다음 구조로 설명한다.

```text
높은 주소

┌───────────────┐
│ Stack         │
├───────────────┤
│ Heap          │
├───────────────┤
│ Data          │
├───────────────┤
│ Code / Text   │
└───────────────┘

낮은 주소
```

각 영역의 역할을 보면 다음과 같다.

### Code / Text

실행할 기계어 명령어가 들어간다.

### Data

전역 변수 등의 데이터가 위치한다.

### Heap

프로그램 실행 중 동적으로 확보하는 메모리 영역이다.

### Stack

지역 변수와 함수 호출과 관련된 정보 등이 사용되는 영역이다.

예를 들어

```c
int a = 3;
int b = 5;
int c = a + b;
```

와 같은 지역 변수는 실행 과정에서 Stack과 연결된다.

---

## 4. 가상 주소와 실제 RAM

프로세스가 사용하는 주소와 실제 RAM의 물리 주소는 그대로 같다고 볼 수 없다.

운영체제는 페이지 테이블을 이용해

```text
Virtual Address
        ↕
Physical Address
```

를 연결한다.

프로세스 입장에서는 자신만의 메모리 공간을 가지고 있는 것처럼 동작한다.

---

## 5. 폰 노이만 구조

이제 CPU와 메모리를 연결해보자.

폰 노이만 구조의 가장 중요한 특징은

> 명령어와 데이터가 같은 메모리에 저장된다.

는 것이다.

단순화하면 다음과 같다.

```text
             CPU
      ┌──────────────┐
      │ CU           │
      │ ALU          │
      │ Register     │
      │ PC / IR      │
      └───────┬──────┘
              │
             Bus
              │
      ┌───────▼──────┐
      │     RAM      │
      │ 명령어        │
      │ 데이터        │
      └──────────────┘
```

CPU는 메모리에서 명령어를 읽고 필요한 데이터를 가져와 연산한다.

---

## 6. OS가 CPU에게 실행을 넘긴다

프로세스를 만들고 필요한 메모리 구성이 끝나면 운영체제는 CPU가 실행을 시작할 수 있도록 한다.

이때 중요한 레지스터가 **PC(Program Counter)**다.

PC는

> 다음에 실행할 명령어의 주소

를 저장한다.

운영체제가 프로그램의 시작 위치를 설정하면 CPU는 해당 주소부터 명령어를 읽기 시작한다.

---

## 7. 일반 프로그램은 하드웨어를 마음대로 사용할 수 없다

다음 코드를 보자.

```c
printf("%d\n", c);
```

화면에 숫자를 출력하는 간단한 코드다.

하지만 일반 프로세스가 화면 출력 장치를 직접 제어하는 것은 아니다.

CPU에는 문서 기준으로 다음 실행 모드가 있다.

```text
User Mode
Kernel Mode
```

일반 프로그램은 User Mode에서 실행된다.

파일 접근이나 출력 등 운영체제 기능이 필요하면 **System Call**을 이용한다.

```text
User Program
    ↓
printf()
    ↓
write()
    ↓
System Call
    ↓
Kernel Mode
    ↓
OS
    ↓
장치 처리
```

작업이 끝나면 다시 User Mode로 돌아온다.

---

## 8. 프로세스는 항상 CPU를 사용하는 것이 아니다

컴퓨터에는 여러 프로세스가 존재한다.

모든 프로세스가 동시에 하나의 CPU를 독점할 수는 없다.

따라서 운영체제는 프로세스를 여러 상태로 관리한다.

대표적인 상태는 다음과 같다.

```text
New
Ready
Running
Waiting
Terminated
```

---

## 9. New

프로세스가 생성되는 상태다.

OS가 PCB를 만들고 필요한 메모리 등을 준비한다.

---

## 10. Ready

프로세스 실행 준비는 끝났지만 CPU를 아직 받지 못한 상태다.

```text
실행 준비 완료
+
CPU만 기다리는 상태
```

Ready Queue에서 자신의 실행 순서를 기다린다.

---

## 11. Running

현재 CPU를 실제로 사용하고 있는 상태다.

CPU가 명령어를

```text
Fetch
Decode
Execute
```

하는 상태가 바로 Running이다.

---

## 12. Waiting / Blocked

프로세스가 어떤 이벤트를 기다리는 상태다.

예를 들어 디스크에서 데이터를 읽는 중이라면 CPU가 있어도 바로 다음 명령을 실행할 수 없다.

그래서 CPU를 다른 프로세스에 넘긴다.

---

## 13. Ready와 Waiting은 다르다

이 둘은 자주 혼동된다.

### Ready

```text
CPU만 받으면 즉시 실행 가능
```

### Waiting

```text
CPU를 받아도 실행할 수 없음
I/O 등의 이벤트 완료가 필요
```

이 차이가 핵심이다.

---

## 14. 프로세스 상태 전이

대표적인 전이는 다음과 같다.

```text
New → Ready
실행 준비 완료

Ready → Running
Scheduler가 CPU 할당

Running → Ready
Time Slice 만료

Running → Waiting
I/O 요청

Waiting → Ready
I/O 완료

Running → Terminated
프로그램 종료
```

---

## 15. Time Slice와 선점형 스케줄링

하나의 프로세스가 CPU를 계속 독점하면 다른 프로그램을 실행할 수 없다.

그래서 운영체제는 일정 시간이 지나면 현재 프로세스의 CPU 사용을 중단하고 다른 프로세스에 CPU를 할당한다.

```text
P1 Running

↓ Time Slice 만료

P1 Ready

P2 Ready

↓ Scheduler

P2 Running
```

이런 방식을 **Preemptive Scheduling**이라고 한다.

여러 프로세스가 짧은 시간 동안 빠르게 번갈아 실행되기 때문에 사용자 입장에서는 프로그램이 동시에 실행되는 것처럼 보인다.

---

## 16. Context Switching

그렇다면 실행 중이던 프로세스를 멈췄다가 나중에 어떻게 정확히 이어서 실행할까?

운영체제는 프로세스의 상태를 PCB(Process Control Block)에 저장한다.

예를 들어

```text
Process ID
State
Program Counter
Register
Memory Information
```

등이 저장된다.

```text
P1 Running

↓ 저장

PCB(P1)

↓ P2 상태 복원

PCB(P2)

↓

P2 Running
```

이 과정을 **Context Switching**이라고 한다.

---

## 17. 프로그램이 종료되면

`main()`에서

```c
return 0;
```

을 만나면 프로그램은 종료 절차에 들어간다.

운영체제는 프로세스가 사용하던 자원을 회수한다.

문서의 흐름은 다음과 같이 정리할 수 있다.

```text
return 0
 ↓
프로세스 종료
 ↓
OS
 ↓
메모리 회수
 ↓
프로세스 정보 정리
 ↓
다른 프로세스 실행
```

## 마무리

프로그램 실행을 운영체제 관점에서 보면 다음과 같다.

```text
Executable
    ↓
OS
    ↓
Process
    ↓
Virtual Memory
    ↓
Ready
    ↓
Running
    ↓
System Call / Waiting
    ↓
Running
    ↓
Terminated
```
